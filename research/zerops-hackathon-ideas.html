02 · Platform signal

What Zerops wants you to show

Zerops is project → service → container on a dedicated private VXLAN. Demo the managed catalog and optional ZCP agent loop — not a static deploy.

High signal · aim for 2–3

  • Multi-service private net (FE + API + worker + managed deps)
  • ZCP in the ship story: prompt → deploy → verify → live URL
  • Living zerops.yaml / import YAML
  • Managed DB/cache/queue/storage as load-bearing
  • Visible async: job states, queues, object keys
  • /architecture page with real hostnames

Low signal · avoid as sole claim

  • Static site “deployed on Zerops”
  • Single-container CRUD with no managed DB story
  • In-memory fake “database”
  • Platform as afterthought in the README

Managed catalog on one network: Postgres, Valkey, NATS, Meilisearch/Qdrant, S3 object storage — addressable as db:5432, cache:6379.

03 · How winners look

Judging criteria (ranked)

From PaaS hackathon winners + this event’s rules. Optimize for doubt removal under time pressure.

# Criterion Why it separates winners
1 Live demo end-to-end Working URL beats ambitious slides every time
2 One-sentence identity “Tool that does X for Y” — no center, no recall
3 Scope matches 48h Complete narrow product > half-built platform
4 Deep platform use Multi-service primitives, not “hosted on X”
5 Specific user / pain Real annoyance beats invented market size
6 Golden-path polish Seed data, persistence, two-session survival
7 Story + video + social Required shape; social track is a second prize
8 Honest limits + AI disclosure Trust; you must defend architecture

Anti-patterns

Hello World Overscope “platform for X” No live URL In-memory DB Slide deck instead of product AI black box First deploy last hour Platform as afterthought
